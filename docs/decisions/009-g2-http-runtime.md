# ADR 009 — NGINX and PHP-FPM with an internal gateway

G2 replaces the PHP development server with PHP 8.4.26 FPM Bookworm and NGINX 1.30.5 Alpine, retaining locked PHP dependencies. NGINX 1.30.5 is the stable version listed by the [official download page](https://nginx.org/en/download.html) inspected on 2026-10-11. Resolved image digests are recorded in G2 evidence. No privileged host installation.

Each API/exporter pod has four static FPM children and a nonroot NGINX HTTP sidecar. FPM remains internal on port 9000; Kubernetes Services expose only HTTP 8080. Docker Compose uses a separate HTTP container to reach its FPM service. Configuration sets bounded connect/read/termination timeouts, body size, and request recycling. FPM inherits only the existing lab environment; stdout/stderr preserve structured application logs. No application file is served directly by NGINX: every request uses the fixed Laravel front controller. Graceful API shutdown sends FPM/NGINX QUIT after a short endpoint propagation delay; queue workers retain TERM shutdown semantics. See the [PHP FPM configuration manual](https://www.php.net/manual/en/install.fpm.configuration.php).

A separate internal NGINX gateway proxies each request to the Kubernetes API ClusterIP without upstream connection reuse or automatic request retries. Kubernetes routes independent connections across eligible API endpoints. The `X-Lab-API-Pod` response header identifies the serving pod for experimental distribution checks; it is not a metric label. Client measurements include gateway/FPM admission, telemetry writes, and response/network time. Structured edge/gateway logs include request duration and bounded traffic class, with correlation IDs only in logs. Existing middleware SLI semantics remain explicitly narrower and do not silently become a full edge SLI. [NGINX upstream documentation](https://nginx.org/en/docs/http/ngx_http_upstream_module.html) describes connection handling.

This runtime choice removes a development-server limit; it does not establish production deployment, security hardening completeness, or production capacity. No cache, long-lived PHP application server, external ingress, or new framework is added.
