# Atomic per-report Redis notifications

G3's queue surplus was a hypothesis from sampled aggregate gauges. G4's bounded before-change worker pause directly observed five waiting notifications for each synthetic report, confirming repeated publication. PostgreSQL pending rows remain authoritative; do not simply lengthen the five-second reservation or replace fenced claims with a cache lock.

The pinned Laravel 13.34.0 RedisQueue already creates framework payloads and manages ready/reserved/delayed notifications. Extend only publication for ProcessReport: one Lua operation checks the report's transport guard, appends its framework-created payload and notify entry, and creates the owner-token guard. Predictable wrong-type errors are checked before writes because Lua isolation is not rollback on runtime error. Use the same Redis connection/database for queue and guard; no separate cache or dependency.

The report's five-second PostgreSQL dispatch reservation remains unchanged. A dispatcher exiting before Redis publication leaves no guard/payload; reconciliation republishes. If publication completes but acknowledgement is lost, the guard suppresses repeated waiting copies. It does not prove completion. After SQL claim/no-op commits, the handler releases only its matching guard token. A stale delivery cannot delete a newer token. A native failed-job listener releases the matching guard if reserved delivery exhausts transport attempts before handle; pending SQL state is reconciled afterward. Business attempts remain bounded at three, native queue retry_after at 20 seconds, lease at 15 seconds and worker timeout at ten seconds.

Guards have a 24-hour safety expiry, limiting abandoned metadata. That TTL is not a 60-second timeliness promise; very long waiting or selectively corrupted Redis state can permit duplicates or delay recovery. Whole queue/guard state loss is recovered from PostgreSQL. Existing completed/failed state and fenced results must tolerate duplicate delivery. The lab uses single Redis, not Redis Cluster; Lua slot/cluster support is outside this goal. Legacy payloads without guard metadata keep ordinary native handling.

Real-Redis tests use database 15, lab_test and unique queue names; cleanup deletes only keys owned by that test. No live Redis flush, queue deletion or database reset occurs. Controlled project worker pauses restore the prior replica count in finally. Queue IDs/tokens are transport fields and logs, never metric labels. Dispatch counters must distinguish actual publication, suppression and transport error without treating a deferred-return value as proof.

References: [Laravel queues](https://laravel.com/docs/13.x/queues), [pinned RedisQueue source](https://github.com/laravel/framework/blob/v13.34.0/src/Illuminate/Queue/RedisQueue.php), [pinned connector](https://github.com/laravel/framework/blob/v13.34.0/src/Illuminate/Queue/Connectors/RedisConnector.php), [Redis script semantics](https://redis.io/docs/latest/develop/programmability/eval-intro/). No dependency/resource/schema upgrade is required. Native unique-job locks were considered, but their separate lock-before-enqueue window does not satisfy atomic publication without additional recovery work.

Validation/results and remaining limits belong in docs/g4/validation.md and evidence/g4/. Rollback restores the native Redis driver after quiescing the project queue; PostgreSQL records/results are never reset. Guards left from the new driver are ignored by the old driver and expire; the old driver's measured amplification returns as well.
