# ADR 010 — retained local telemetry storage

G2 uses project-owned `.runtime/observability/COMPONENT` directories mounted into only the dedicated kind node at `/lab-observability`. Terraform owns six static Retain PV/PVC pairs for Prometheus, Loki, Grafana, Alertmanager, Mailpit, and Alloy. Single-writer deployments use Recreate rather than overlapping rolling writers. Each narrowly scoped init container only sets ownership/permissions on its own data volume; application processes remain nonroot with read-only root filesystems and dropped capabilities. PostgreSQL keeps its existing separate retained host directory.

Bootstrap creates the kind bind mount explicitly. Deploy refuses an existing node without that mount rather than silently writing telemetry into disposable node storage. Teardown preserves both host directories and private backups. Advertised PVC sizes are not filesystem quotas. Prometheus retains up to 31 days or 2 GiB of blocks, whichever retention policy triggers first; WAL/compaction can temporarily exceed that block limit. See [Prometheus local storage](https://prometheus.io/docs/prometheus/latest/storage/). Loki retains its existing time-based policy; monitor host free space and stop tests before disk pressure. No full 30-day retention guarantee is inferred from configuration.

G1 used emptyDir. Initial migration exports service data while briefly freezing each process, includes WAL/state, and always resumes it. The source processes and destination paths are resolved from this project's verified pod/container and dedicated node only. Exports are private, crash-consistent filesystem copies, not application-consistent or off-host backups. This method may lose uncommitted/tail state or encounter recovery issues; retain failed observations and verify pre-recorded historical metrics, correlated completed-report logs, an inbox message, and a Grafana annotation after restoration. It does not prove completeness of all historical samples. A pre-migration inbox query was empty; the reason is unknown. G1's 36 exported messages remain in evidence, and a clearly labeled local notification fixture seeds the G2 inbox marker without pretending it is an SLO event.

Persistence tests include both full dedicated cluster recreation and subsequent pod recreation. Historical markers must survive, all six claims must be Bound, and new acceptance/completion and observability checks must pass. Local disk failure, backup/HA for telemetry, secure cross-host migration, and exactly-once log ingestion are outside scope. Alloy state retention reduces replay risk but does not establish exactly-once logs. Logical PostgreSQL backup/restore is a separate exercise, not a backup of telemetry.
