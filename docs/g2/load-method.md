# Sustained local load and worker interruption

`make g2-load` uses the existing standard-library scheduled-arrival approach through the gateway and Kubernetes API Service. Exploratory offered rates are 10, 30, 60, 90, 120, 180, and 240 requests/s for 180 seconds each. Stop at the first latency/error/timeliness breach or generator limitation. These are bounded inputs, not capacity targets. Confirm the highest observed passing rate for 600 seconds after all prior accepted work reaches a terminal state. If no rate passes, the generator limits the measurement, or the backlog does not drain, retain the failure and do not claim the confirmation passed.

Acceptance response errors/timeouts remain in samples, even if the database later shows committed acceptance. Client latency includes gateway/FPM admission and durable metric-write/response overhead; middleware timing is narrower. Observe `X-Lab-API-Pod` distribution and require both ready replicas. This tests Kubernetes Service connection distribution behind one local gateway, not an external ingress or production network. The gateway does not retry upstream requests. Keep unique idempotency keys and classify every request as load.

At each step, wait until every committed accepted report's deadline expires. Failed/unfinished reports and late completions are misses. Stop criteria: HTTP error ratio above 1%, fewer than 99% of client responses within 500 ms, or fewer than 99% of expired reports completed within 60 seconds. A p99 scheduled-arrival delay above 250 ms invalidates precise offered-rate attribution. Preserve raw samples, committed cohorts, both API pod counts, resource ranges, UTC timing, SHA, and manifest configuration. Ten-minute confirmation remains a bounded local observation, not indefinite sustainable throughput or a 30-day SLO.

`make g2-interruption` runs a separate 10 requests/s, 60-second load cohort while two synthetic fault reports use bounded four-second simulator latency. Correlate each report in processing attempt one to a different worker pod and dedicated-node PID, recheck active states, then kill both worker processes together. Pod deletion alone is insufficient proof. Require both reports completed on attempt two, one stored result each, and passing background load. Preserve pre-kill logs/PIDs and final database results. Kubernetes must restart the workers and the reconciler must recover expired leases. Fault inputs remain outside normal SLOs. No arbitrary node/database outage or recovery probability is inferred.
