# Alertas por e-mail local
Caixa: alerts@lab.test; remetente alertmanager@lab.test. Mailpit apenas recebe/captura SMTP, sem relay/forwarding externo. Acesse UI autenticada via make mail-up; LAB_BIND_ADDRESS pode selecionar o IP da rede confiável. Credencial lab/LAB_TOKEN vem do Secret local, nunca de arquivo commitado. SMTP e métricas ficam internos.

1. Verifique Prometheus /api/v1/rules e /api/v1/alerts: regras saudáveis, estado pending/firing. Confirme janelas, elegibilidade e modo; notification-fixture significa teste de envio, accelerated-demonstration significa fault cohort, ambos diferentes do SLO normal.
2. Verifique /api/v1/alertmanagers no Prometheus: alertmanager:9093 ativo. Em Alertmanager /api/v2/alerts e /api/v2/status confira recebimento/configuração. Não criar silences para esconder testes falhos.
3. Veja up{job="alertmanager"}, up{job="mailpit"}, alertmanager_notifications_failed_total{integration="email"} e logs apenas desses deployments. SMTPsmarthost=mailpit:1025, TLSfalse para esta rede interna de lab. Destinatário permitido é somente alerts@lab.test; não substituir por endereço externo no G1.
4. A caixa API /api/v1/messages retorna401 sem autenticação e lista mensagens com Basic lab/LAB_TOKEN. Preserve mensagens JSON antes de rollouts; não limpar a caixa para fazer teste passar. Estados firing e resolved geram mensagens separadas; group_wait5s, group_interval10s, repeat1h reduzem duplicatas.
5. make alert-test pode parar scheduler e hostcollector por poucos minutos. finally restaura ambos; após interrupção abrupta, restaure replicas1 via contexto explícito do projeto e execute make host-metrics-up. Terraform continua dono da configuração; scale durante o experimento é uma falha temporária, não gerência alternativa permanente. Confirme make smoke, todos targetsUP e resolução dos alertas. Um relatório failed permanecefailed após recuperação; o alerta de fault só resolve quando o deadline sai do cohort5m, sem editar registros.

Limites: SLOBurn* é validado por promtool em janelas simuladas e envio por fixtures. O teste ao vivo valida LabDemoProcessingMiss, TelemetryUnavailable e InfrastructureTelemetryUnavailable com entrega/resolução real. Não equivale a observação de30dias, nem a entrega externa. Mailpit/AlertmanageremptyDir não são armazenamento permanente; use evidence/email-ID para resultados duráveis.
