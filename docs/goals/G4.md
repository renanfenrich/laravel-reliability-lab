## Design boundaries

Reuse pinned Laravel 13.34.0/Redis 8.2.2 and native RedisQueue consumption/reservation behavior. Native unique jobs alone place lock acquisition before enqueue and can strand acceptance when a dispatcher exits in that gap; do not trade queue amplification for invisible pending work. Evaluate a narrow RedisQueue publication extension with atomic Lua, using framework-created payloads and no untrusted deserialization. Validate predictable script errors before writes; Lua execution isolation does not roll back writes on runtime errors. A guard is transport state, not business truth.

A per-notification owner token must prevent stale delivery/failure cleanup from clearing a newer publication. Release only after the SQL claim/no-op decision commits. Framework failures before handle must release the matching guard; Redis retry_after remains 20 seconds and business attempt/lease/retry limits remain unchanged. A finite 24-hour guard TTL bounds abandoned metadata, not a timeliness guarantee; very long waiting/corrupted selective state can permit duplicate delivery, which database fencing must still tolerate. Whole transport-state loss is recovered from pending records. Test crash-before-publication, published-but-unacknowledged, pre-claim termination and stale-owner races explicitly.

Application tests must use Compose lab_test plus a separate Redis database and unique synthetic queue names. Never flush the live queue or Redis database, reset reports, overwrite a database, or scan/export unbounded raw queue payloads. A controlled Kubernetes worker pause is bounded, restores the prior replica count in finally, and starts only with quiescent project cohorts/queues. Whole live Redis loss is not needed: reproduce transport-state deletion only in the isolated test database/queue. Keep authentication, idempotency, committed acceptance, visible terminal failures and immutable deadlines intact.

## Measurement and acceptance

After change repeat the same experiment: no repeated waiting notification within the guard window, suppressed-dispatch counter visible, exactly one result per report after resume and queue/guard cleanup observed. Do not turn a paused-worker deadline miss into a success if it expires.

Use existing scheduled-arrival semantics, resource limits, simulator defaults and traffic policy. Stop increasing rate on saturation/generator limits. Wait for all accepted records to finish and ready/reserved/delayed notification depth to reach zero before confirmation; record both kinds of drain and any timeout. Higher throughput is not promised.
