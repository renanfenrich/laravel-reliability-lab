# Evidence interpretation

Every experiment stores UTC timestamps, the source commit, manifest/workload configuration, host resources, offered rate/duration, client latency/error samples, committed deadline cohorts, alert histories and resource samples. versions-final.json captures exact deployed image IDs and source/config checksums; composer.lock pins package resolution. commands.jsonl records final-command start/end/duration/exit/SHA. Earlier build/deploy logs lack a wrapper timestamp for every command; retain observed timestamps and never reconstruct exact durations from guesses.

PASS means the stated check completed, not all service objectives held. An intentional fault yielding visible failed reports is a successful experiment. Load breaches stay in raw samples and capacity report. A failed worker-interruption injection is INVALID for proving recovery; real PID SIGKILL must correlate to processing report and a subsequent attempt. An HTTP EOF artifact is INVALID for estimating application saturation; client first-byte and total durations expose the discrepancy. Corrected experiments get their own SHA/time and old results remain intact.

Actual 30-day SLO attainment, production capacity/HA, external notification delivery, multi-region/cloud operation, full disaster recovery, and browser accessibility remain unexecuted or unestablished. Hosted CI had not run during the original local experiments; its final result after publication is not established in this report. Local SMTP capture was subsequently validated separately. Synthetic promtool fixtures test rule mathematics/behavior, not actual elapsed service history. Database and HTTP counts have separate event populations. Normal, load and fault submissions are classified explicitly; a pre-framing run incorrectly tagged fault status polling as normal, so its normal HTTP SLI interval is unsuitable for compliance. The corrected helper tags all fault polls; acceptance/completion classifications were unaffected.

Workstation activity, process startup, loopback forwarding, short bursts, limited sample size, a single selected API pod, shared counter row contention and ephemeral telemetry storage limit generalization. Inspect scheduling lateness before assigning a client-generator limit to the service. A capacity knee inferred from trends must be labeled inference unless correlated CPU/queue evidence establishes it.
